### 三、模型选择：开源/闭源 × 中/美（07:16–11:16）

- 孟老师建议在“中美各一个模型”基础上再加一个维度——**开源 vs 闭源**，形成四模型设计。

- 初步共识：**DeepSeek（中国开源）**、**Claude 或 OpenAI（国外闭源，Huhe负责）**。

- 国内闭源候选：**智谱 GLM** 与**豆包（字节 seed，闭源）**；苏宇轩认为两者在本研究上差别不大，均属国内第一梯队。

- 选择考量：并非“哪个好”，而要**便于日后外审**——reviewer 一看就知道是耳熟能详的国内闭源模型（Huhe提到其父母多用豆包、智谱较少见，故有顾虑），倾向选**智谱**。

- 国外开源：一时找不到有名的国外开源模型；苏宇轩建议**用同一模型的开源与闭源版本做对比以控制变量**，故暂时不列国外开源模型，实为三模型（DeepSeek \+ 智谱/豆包 \+ OpenAI/Anthropic）。

### 四、执行细节：1000 次重复、时段错开与变量存储（11:16–14:23）

- 拟先跑约 **1000 个 test run**（both generic AI 与 government AI），并考虑**早/中/晚三个时段**发送（如 300\+300\+300）；若操作困难，至少错开**工作时间 vs 非工作时间**（北京时间 8:00–17:00 及之后）。

- 理由：虽认为模型 performance 本身不变，但作为额外的 precaution，检验不同时段是否产生影响。

- 苏宇轩需在输出中**新增“模型执行任务的时间”变量**。

- 计划：先在 DeepSeek（开源、试错成本低）上 run 1000 个，分析节点无误后，再到成本较高的闭源/OpenAI 上做**重复实验**。

### 五、实验任务与“1000 次”的含义（15:18–23:16）

- 任务：向模型发送两段 prompt，做两类评估——**AI 边境防御系统评估** 与 **AI 致命疾病诊断系统评估**（与人类 survey experiment 对照）。

- “1000 次”＝让 AI 做 1000 次选择（每次一个选择格式算一次），因人类样本约 3000 多，AI 需足够重复次数以推断其**隐藏偏好**。

- conjoint 方法参照人类调研：**随机生成**不同 attribute/情景让 AI 选择，一次任务只推断一点，重复 1000 次可较好确定 AI 隐藏偏好；每次为 **context\-free / memory\-free**（仅基于 prompt 与任务，无记忆，token 消耗较小）。

- 苏宇轩据表算出 attribute（研发机构、漏报军事目标、误伤平民、作战时效、问责机制各 3 选项）= 3^5 = **243** 组合，疑惑应跑 243 次；Huhe解释：不必穷尽，完全模拟人类联合实验的随机过程，且**同一 identical 选择未必得到相同回应**（故需余量检验 identical 回应、并保存执行时间）。

- 结论：**纯随机**，不用专门设计算法，全部 attribute 随机生成，与发给苏宇轩的 conjoint Excel 一致。

### 六、输出变量与后续分析（23:16–25:16）

- 每次调用需记录以下变量：**①调用时间（至少两个时段 variation）②随机任务内容（国家A/B，与 conjoint Excel 对应）③AI 的选择 ④AI 给出的结果/回应文本**。

- 分析分两部分：**算法模拟**（Huhe code 已备好，属重复过程，可一起做）\+ **文本分析**（AI 生成的文本回应，用不同文本分析模型进一步分析，了解其决策过程）。

- Huhe建议先**把文本记录下来**，便于之后分析。
